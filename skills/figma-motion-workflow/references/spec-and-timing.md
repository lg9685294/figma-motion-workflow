# 规格与计时

## 记录什么

轻量任务用表格；多条依赖或频繁调时长时增加 JSON。用一个有效规格作本轮制作依据，历史修改单独列出。

| 字段 | 内容 |
| --- | --- |
| target | Figma 文件／节点、对象、属性；旋转写参照坐标和轴心 |
| from / to | 数值与单位；缩放是原尺寸比例还是父组比例 |
| trigger | 绝对开始时刻，或哪条轨道到哪个属性阈值／结束后多久 |
| duration_ms | 本阶段时长；停留也作为独立阶段记录 |
| easing | 真实控制点、Linear 或可回溯的源曲线；名称未知时标待核验 |
| status / source | confirmed、carried、derived、proposed、unresolved；定位到消息／源节点／测量 |
| end / affected | 计算结束点和下游依赖；整段结束是否与目标一致 |

修改记录同时保留旧值、新值和被覆盖字段。几何、配色、时序分别管理；同一条新消息不自动覆盖整个方案。

## 进度阈值

设路径从 `a` 开始，时长 `d`，归一化时间 `u=(t-a)/d`，实际进度 `p=E(u)`。要求进度 `q` 时触发，应求 `E(u)=q`，再算 `t=a+d*u`。

对于 cubic Bézier，曲线参数记 `s`，横向 `x(s)` 表示时间，纵向 `y(s)` 表示属性进度。先解 `y(s)=q`，再取 `u=x(s)`；不能直接把 `s` 或 `q` 当作时间比例。

阈值的属性需要明确：路径显现长度、trim 值、透明度、缩放等。“总体显现到 90%”若由多属性组成，先确定驱动轨道。路径长度比例不等于包围盒宽度比例。非匀速路径映射或非 0→100 的 trim，要先把目标转换为轨道归一化进度。

弹簧和超调曲线可能多次越过阈值，须明确第一次到达／最后稳定等语义，读取采样数据后计算。本辅助脚本只处理单调、单阶段进度。

已明确提供解析公式时，可直接反解该公式，无需强行转换成脚本输入。例如 `p=1-(1-u)^3` 的反函数为 `u=1-(1-p)^(1/3)`；它也严格等价于 `cubic-bezier(1/3,1,2/3,1)`。若要交给脚本，先把分数换成足够精度的小数。其他公式只有证明等价后才能这样转换，不能用相似外观的曲线替代。

## 辅助脚本

`scripts/timeline.py` 仅用 Python 标准库。命令从 skill 目录执行，或将命令中的脚本路径换成绝对路径。

```bash
python3 scripts/timeline.py threshold --start-ms 100 --duration-ms 300 --progress 0.9 --easing linear
python3 scripts/timeline.py audit assets/timeline.example.json
```

`assets/timeline.example.json` 是格式演示，值均为示例，不继承任何 案例项目 最终参数。将它复制到当前项目后修改；不覆盖 skill 内模板。

审计格式的最小示例：

```json
{
  "declared_total_ms": 470,
  "events": [
    {"id": "line", "start_ms": 100, "duration_ms": 300, "easing": "linear"},
    {"id": "detail", "duration_ms": 100, "trigger": {"event": "line", "at": "progress", "progress": 0.9, "delay_ms": 0}}
  ]
}
```

每个 event 只能选 `start_ms` 或 `trigger`。`at` 为 `end` 或 `progress`；百分比触发在父 event 上读取 easing。一个 event 代表一个用于计时的属性阶段，其他几何与来源可放在项目参数表里。

只有“某轨道在 520ms 结束”而没有开始时刻时，可用明确标注的零时长完成标记把它计入结束审计：

```json
{"id": "scale_completed", "start_ms": 520, "duration_ms": 0, "marker_only": true}
```

`marker_only` 是给制作者看的元数据，脚本按零时长事件计时。它只代表已知终点，不能冒充完整缩放轨道；起点、幅度和曲线仍在项目规格中保持待核验。

返回已解析事件起终点、`resolved_total_ms`、`complete` 和 `issues`。`declared_total_ms` 用于检测声明与计算冲突。退出码 `0` 表示所列计时关系通过，`2` 表示存在未解析、非法或不一致项；按实际 JSON 中的 issues 处理。

没有真实曲线时，可保留 `easing: "ease-out"` 并得到未解析报告，不能为了让校验通过而改成 Linear。无需进度触发时，缺省曲线不影响单纯的开始／结束计时，但仍需在项目规格里标出曲线待核验。

脚本不会判断来源是否最终生效，不会识别漏录的动画轨道，也不会证明路径真的长到目标位置。`complete` 只表示所给计时数据可解析且通过审计，不能作为整个动效完成标记。

## 总时长与精度

整段结束是所有实际可见属性结束的最大值。主体归位后还有表情、回落或回正时，这些阶段仍计入整段。预滚不计入点击后的结束时间。

保留内部计算精度，展示时按源数据精度取舍。录屏按有效画面帧率估算误差；重复帧／补帧不能提高测量精度。明确测量误差与时间轴数值精度的区别。要求对齐某个整段目标时，也检查最后的缩放、旋转及辅助轨道，不只修改标称值。
