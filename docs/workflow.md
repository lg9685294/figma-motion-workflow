# 从反复调试中提炼的动效制作方法

## 为什么先做规格

图形不一致、路径交点露白和后续轨道拖尾，是三个不同问题。只增加提示词长度难以解决。这个工作流把它们依次处理：先锁定几何，再明确动作事件和依赖，最后调整节奏并回到实际播放验收。

## 先收拢生效要求

将每次修改写成：`对象／属性 → 旧值 → 新值 → 单位 → 依据 → 受影响依赖`。将来源状态分为确认、沿用、推算、建议与待核验；被覆盖和撤回的值保留历史，退出当前规格。

用户只撤回一条试验时，恢复这条涉及的属性、依赖时序和参数表。其他已接受调整继续生效。单一节点的持续修改或改名不足以证明存在独立备份。

## 锁定几何再增加动作

对照真实源矢量检查最终轮廓、孔洞、线宽、端帽、连接点和渐变。以最终轮廓作为生长揭示对象，避免过程画一条近似线、末帧再换成原图。

先做小进度测试，确认起点与方向。连接在主体上的线条应使用一致的坐标关系，在运动全程接住主体。交叉路径可能需要拆开揭示区域，以避免提前露线、尖刺和缺口。

## 用事件连接动作

“长到 90%”必须说明是路径长度、trim 值、透明度还是另一个属性。若实际进度 `p=E(u)`，阈值 `q` 的时间是 `a+d*E⁻¹(q)`。只有 Linear 能直接乘以时间比例。

只有曲线名称而没有控制点时，保留阈值关系并读取真实曲线。修改曲线、路径或阶段时长后，重算下游触发。整段结束取主体、线条、表情、回弹和回正等所有可见轨道的最后终点。

## 分开验收

| 检查层 | 需要的证据 |
| --- | --- |
| 源规格 | 当前节点、属性轨道与曲线读回 |
| 视觉 | 实际尺寸正常播放；起笔、交点、阈值和结束附近逐帧 |
| 交互 | 实例点击、重复触发、切换后返回和重播 |
| 导出 | 实际生成的文件可打开，内容及时间一致 |

截图能证明静态外观，计时审计能检查输入的依赖关系；它们都不能单独证明整段 Figma 动效已完成。
